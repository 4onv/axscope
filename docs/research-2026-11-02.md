The saved snapshot format exposes a separate testing opportunity. The tree contains roles, names and parent-child relationships. Its response distinguishes capture completeness from evidence supporting live identity. That distinction matters when looking at a saved fixture with a single visible match. ## The project choice

AxScope checks whether a declared role and name still select one candidate in each recorded state. Its suggestion workflow searches for named ancestor scopes that work across the supplied states. For example, adding a second “Save” button can break a global selector while the “Save” under “Billing” stays unique. A maintainer can exercise the same target contract on fixtures from multiple app versions during CI.

That workflow is an inference from the upstream failures. The pull requests solve live resolver problems and do not establish demand for this separate fixture tool. Saved states provide evidence about the captured tree. Only a live test can verify element identity, delivered actions, or how the app responds. Intentional localization or label changes deserve human review. Demo captures are synthetic.

## Related tools

| Tool | Existing capability | When it fits |
| --- | --- | --- |
| [agent-desktop](https://github.com/vercel-labs/agent-desktop) | Captures native trees, resolves refs and verifies action outcomes where possible | Inspect or operate a running desktop app |
| [ax-cli](https://github.com/watzon/ax-cli) | Saves macOS accessibility snapshots, compares captures and resolves reusable selectors | Inspect a macOS application and investigate general tree changes |
| [Playwright](https://playwright.dev/docs/aria-snapshots) | Checks a browser page's accessibility tree against ARIA snapshot templates | Run web UI regression tests within a browser suite |
| [A11yUITests](https://github.com/rwapp/A11yUITests) | Compares XCUI accessibility snapshots with known-good references. The repository is archived | Understand an existing approach to native snapshot regression tests |

AxScope's narrow contribution is checking a developer's specific targets against a collection of exported fixtures and proposing exact named scopes that satisfy all supplied states. Adoption remains unmeasured.
